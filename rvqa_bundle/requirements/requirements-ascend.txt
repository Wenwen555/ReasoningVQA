# WHY EACH OVERRIDE IS NECESSARY

# transformers 4.53.1 -> 4.49.0
#   The LoRA target inventories (inventories/*.json, sha256-checked) are keyed
#   to the LEGACY module prefixes `model.layers.*` / `visual.*` emitted by
#   transformers 4.49.0.  4.50+ renamed / restructured those paths, so the
#   inventory load fails or silently targets the wrong modules.
#
# accelerate 1.0.1 -> 1.13.0
#   The trainer passes `device_map={"": 0}`.  Only newer accelerate versions
#   explicitly detect torch_npu (`is_npu_available()`) and map an INTEGER device
#   argument to `npu:<n>`.  With accelerate 1.0.1 the integer stays a CUDA index,
#   so the model never lands on the NPU.  1.13.0 is the version this mapping was
#   verified against (see setup_envs_ascend.sh smoke test).
